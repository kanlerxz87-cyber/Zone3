The constraint that shapes the AI layer

Associates Program Policies, Participation Requirements section 5, states:

"You will not, without our express prior written approval, use, or allow any third party to use, any Special Links or Program Content to develop machine learning models or related technology."

The brief asks for an AI-powered platform. That is compatible with this rule, but only if the architecture keeps the two activities separate. Using a general-purpose model to draft or edit copy is a different thing from training or fine-tuning a model on Amazon-sourced product data, images, reviews or link data. The second requires written approval first.

Two further restrictions apply to the automation layer. Section 5 of the Commission Income Statement says Associates' tags should only be used to benefit from Amazon Associates commissions, and that Amazon may withhold commissions or terminate participation if it detects an attempt to claim commissions from two programs using the same traffic. The Bonus Event provisions separately disqualify activity generated by "bots or automated software".

Practical rule for this project: automation stays in the back office. It may read your reports, update your pages and draft content for human review. It must never click, visit or transact through your own Special Links, and it must never double-attribute the same traffic — FLAG-17.

Target architecture designed, not yet built

collector
Scheduled job that calls Creators API or PA API for each tracked ASIN and appends one immutable row per run: ASIN, captured-at, price, list price, deal badge, star rating, rating count, Best Sellers Rank, availability. Immutable append-only rows are what make a trend series possible. This is also the only lawful way to display prices — FLAG-01.
store
Append-only table keyed by (ASIN, captured_at), plus a current-state view. Reports read the view; analysis reads the history.
niche scanner
Scheduled capture of the Best Sellers list for the category and its siblings. Ranks over time are the trend signal; a single capture is not — FLAG-18.
link registry
One row per (page, ASIN, tag, sub-tag) with the generated Special Link, the date it was published and the page it lives on. Sub-tags exist so placement can be compared. Note that sub-tags may not be dynamically assigned per visitor.
content pipeline
Draft generation for category hubs, comparisons and buying guides, with a mandatory human review gate and an automated factual check against the store. Any claim about a product has to trace to a stored value or it does not ship.
reporting
Reads Associates Central export data as the source of truth for clicks, conversions and earnings. Do not reimplement this from your own click logging — Amazon's numbers are the ones that get paid.

Build order

  1. Associates account and tag — without it nothing downstream earns (FLAG-05).
  2. Creators API or PA API credentials — the prerequisite for lawful price display and for BSR (FLAG-01, FLAG-03).
  3. Collector plus store, running on a schedule. Nothing else is useful until a history accumulates.
  4. Original content, human-reviewed. This is what Amazon's suitability review looks at (FLAG-13).
  5. Link registry, then reporting, then optimisation.
