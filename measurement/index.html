As an Amazon Associate I earn from qualifying purchases. How we work

Measurement · status: OFF

What is counted here, and what is not

The site has one outbound-click and page-event counter. Production status: OFF. Built and tested. Production not deployed: no durable authorized HTTPS collector host is available. The same-origin development preview runs the real aggregate collector; its counts are test traffic, not campaign evidence. No authorized Associates order or commission report has been obtained. Browser events do not establish conversions.

Status

  • Counter in the browser: built (assets/measure.js). Current setting: OFF.
  • Collector: built as tools/analytics_endpoint.py and self-tested. Not deployed in production. GitHub Pages serves static files only, and GitHub's own documentation says it logs visitor IP addresses for security. The development preview can run a real same-origin collector; preview test events are not campaign evidence.
  • Event names: Canonical default runtime schema as of 2026-11-19: page_view, outbound_click, guide_view, intent_view, flag_view. Retained from the existing default stack; the alternative tracker is retired from runtime injection. The brief does not enumerate event names. Historical alternate schemas remain in the repository, but their tracker is not injected.
  • Conversions: not measured here. Orders and commissions come only from the Associates reports; the campaign ledger stays empty until those reports are entered with their dates.

These columns describe event-body fields, not everything visible to a web server. A network connection necessarily reveals an IP address to its receiving host and can include browser headers such as User-Agent. The collector does not log or retain them; a production host and any proxy require their own logging review.

Rules the counter follows

  • One runtime only; a global initialization guard prevents double counting if the script is accidentally loaded twice.
  • No cookies, localStorage, sessionStorage or visitor identifiers are written by the counter.
  • Global Privacy Control, Do Not Track or Save-Data disables all analytics requests.
  • If enabled is false, endpoint_url is empty or the endpoint is invalid, no analytics request is made.
  • Requests use fetch with credentials omitted, no referrer, text/plain JSON, keepalive and redirect:error. No sendBeacon credential fallback is used.
  • Search text and local suggestion-review choices are never analytics payload fields.

Rules the collector follows

  • Accepts only the five named events, known public page paths and known Amazon host/product-token pairs. Extra fields are discarded; invalid data is rejected.
  • Requires an approved Origin; rejects unknown origins, unsupported content types and payloads over 2 KiB. A global write ceiling limits basic abuse without per-person identifiers.
  • Stores daily aggregate counts only, with 90-UTC-day automatic retention. No raw event rows, IP addresses, user agents, referrers or request logs are stored by the collector.
  • The server clock sets the day; client dates and identifiers are ignored.
  • GET /counts is disabled without the server-side Z3_ANALYTICS_READ_TOKEN and requires Bearer authorization when enabled. No read token is shipped to browsers.
  • The host/reverse proxy/CDN must be configured separately not to retain request logs. This repository cannot certify an undeployed host.
  • Event counts are not unique visitors, eligible sessions, orders, commissions or conversion rates.

Why no visitor-level tracking

Associates Program Participation Requirement 2(b) says that under no circumstances may any sub-tag, other ID or reporting provided in connection with the Associates Program be associated with a specific end user of the site. The counter therefore stores only daily totals per page and per link, never a visitor identifier. Source: Associates Program Policies, Participation Requirements 2(b).
