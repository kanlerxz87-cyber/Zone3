What is counted here, and what is not

The site has an outbound-click and page-event counter. It is built, and it is off: it sends nothing until someone hosts the collector and sets its address. Until then, Amazon's own Associates reports are the only click and order data this project has.

Status

  • Counter in the browser: built (assets/measure.js). Current setting: OFF.
  • Collector: built as tools/analytics_endpoint.py and self-tested. Not hosted. GitHub Pages serves static files only, and GitHub's own documentation says it logs visitor IP addresses for security (the counter does not add to that log, and cannot remove it).
  • Event names: five are proposed below. The brief asks for five defined events but does not name them; the owner must confirm or replace them (flag M38-F-04).
  • Conversions: not measured here. Orders and commissions come only from the Associates reports; the campaign ledger stays empty until those reports are entered with their dates.

The five events (proposed)

EventWhen it firesWhat is sentWhat is never sent

flag_viewLoad of the flagged-for-review page or the publication pass page.event name, page path, UTC day.anything beyond the page path.

Rules the counter follows

  • No cookies, localStorage or sessionStorage are written by the counter.
  • No visitor identifier is generated or sent.
  • If navigator.globalPrivacyControl is true, or Do Not Track is '1', nothing is sent.
  • If endpoint_url is empty or enabled is false, nothing is sent and no network request is made.
  • Sends use navigator.sendBeacon with a text/plain body, so the browser does not read any response.

Rules the collector follows

  • Accepts only the five event names above; anything else returns 400.
  • Stores daily totals per event, page path and link token. It does not store IP addresses, user agents, referrers or request logs.
  • The server clock sets the day. Client-supplied dates are ignored.
  • Read access to totals requires a token set in the environment (Z3_ANALYTICS_READ_TOKEN). Without it, the read endpoint is disabled.

Why no visitor-level tracking

Associates Program Participation Requirement 2(b) says that under no circumstances may any sub-tag, other ID or reporting provided in connection with the Associates Program be associated with a specific end user of the site. The counter therefore stores only daily totals per page and per link, never a visitor identifier. Source: Associates Program Policies, Participation Requirements 2(b).
