Design paths — the brief for the polish, in reviewable options

Three paths, each written so the accepted one becomes a building brief. They are ordered: C decides the surface, A decorates it, B runs it; A and B combine freely. Nothing here is implemented by reading it — record a choice on the review console.

DP-A Shopfront first, lab underneath

Thesis. A buyer decides in seconds at the shelf; the verification machinery stays one click away but never above the fold. The site stops reading like an audit by changing what is FIRST, not by adding decoration.

  1. Open site/index.html with the three-question chooser already built for this purpose (decision D-23 in the brief's list) — move it above the product cards; every answer deep-links to the comparison row it affects.
  2. Give each product card a 'fits you if / not for you if' pair of lines generated ONLY from quoted listing features — the generator already blocks any other sentence (i2_gate G6/G7), so catchiness comes from layout, not from invented claims.
  3. Below the cards, one strip: 'New this week from the guides desk' fed by the same register that now backs feed.xml; dated, never ranked.
  4. Disclosure strip stays exactly where it is (above the fold, every page, repeated in the footer) — the polish must not move it, and the lint enforces that it wasn't.
  5. Keep every dashboard surface (flagged, sources, verification, decision pages) reachable from the footer and the single nav group — already true; do not add nav items, fold new ones in.

Resolves: The look half of SUG-01 and SUG-04; the brief's 'lead with the products' rule; consistent with S-17/S-19 as implemented. · Effort: One generator pass over site/ home + front-door region; no new data files; every gate already exists. · Risk: Low. Worst case the page reverts on a rebuild — the same self-healing pattern the feed uses now covers it.

Do not: No prices, no star ratings, no review counts, no 'bestseller' badge until the API feed exists (2(b)/6(t)); no 'trending' without a dated first-party snapshot (the evidence rule already adopted).

DP-B Magazine desk: voice and cadence carry it

Thesis. The fastest way to stop reading like AI slop is a real editorial calendar with a named human gate: one dated question per week, an author byline, and a 'what changed since last read' box that only a desk that re-reads sources can write.

  1. Adopt the cadence in the review below: one guide per week, each new guide lands in sitemap + feed automatically because both are register-driven now.
  2. Add a byline block ('Field Notes desk — reviewed by: <name>') once Q5 names the human reviewer; until then the reviewed_by line stating 'no human editor' stays (it is already there; polishing would mean removing it, which we will not do).
  3. Two held topics become publishable ONLY with owner inputs: testing/first-hand use (Q6) or the API for figures (Q4); do not write them softer to ship them.
  4. Keep titles question-shaped like the five live guides; the brief's own suggested titles are all published — the next topic should come from the D8 query report, not from instinct.

Resolves: SUG-02, SUG-03, SUG-10, S-07's cadence half, and the 'catchy trendy articles' ask — honestly: catchy within what the compliance gates allow. · Effort: Editorial continuity, not code: the machinery (register, lint, feed, sitemap) already carries a weekly page in under an hour. · Risk: Cadence decays without a named owner; the site must never ship a 'latest' widget that goes stale — the register dates everything for exactly this reason.

Do not: No synthetic social proof, no 'most popular', no AI-author persona names.

DP-C Consolidate, then decorate

Thesis. Three parallel reader layers (site/, read/, marketing/) say near-the-same things about the same three products in three voices. That is both the strongest 'generated' tell and the reason search cannot pick a winner. One canonical layer fixes the findability ask and most of the slop feel at once.

  1. Owner answers Q12 (choose the canonical layer). Recommendation recorded here: promote site/ (the layer with the working house lint and release gates) and mark read/ + marketing/ as companion research with cross-links, not duplicates.
  2. One navigation, one feed (the new feed.xml grows to cover the layer chosen), one sitemap (already covers everything; consolidation is a link-and-banner change, not a build change).
  3. Fold the surviving extras (photography once S-18 decides, any API data once Q4 clears) into the chosen layer only, so polish is not written three times.

Resolves: 'One site to index and a reason to rank it' from the brief; Z14-F-04; the duplication note; most of Q7's brand-open residue. · Effort: Small edits, but touches the most shared files in the repo — must be ONE integration session (per the coordination protocol), not three parallel ones. · Risk: Link churn: internal cross-links and the sitemap shift. The gates in scripts/ catch every broken one before push.

Do not: Do not delete the losing layers (history rule: archives stay); do not hand-merge the three feeds of copy into one without re-running every gate on the result.

Publishing cadence (proposed)

Catchy, topic-driven articles are the main organic-traffic lever for an affiliate site, and the topic plan already anchors every title to a fact printed on the listing, so the content has something real to say instead of generic filler.

SUG-03Human-review gate to remove the AI-slop feel
Before publication, every article passes a review checklist: specific verified specs, no generic filler, no invented experience, the disclosure shown near the recommendation, and a named reviewer. A short 'how this was written' note states which facts were read from which Amazon page.
The brief asks that the site not read like AI slop. The most defensible way to achieve that without inventing claims is a visible editorial process: every statement traces to an Amazon page, and every article says what was and was not verified.
  • FTC: you cannot talk about your experience with a product you have not tried. S07
  • FTC: the disclosure must be hard to miss and placed close to the recommendation; an 'affiliate link' label or a buy button alone is not an adequate disclosure. S44
Accepted
