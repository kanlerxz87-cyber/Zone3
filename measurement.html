The five events

Exactly five events are defined. Nothing else is emitted by this site's own code, and the collector rejects any other event id, so the set cannot drift quietly.

Privacy rules, in force in the code

  • No cookies, no localStorage profiles, no fingerprinting, no cross-site identifiers — the browser sends no user identifier at all.
  • Do Not Track and Global Privacy Control switch the tracker off completely; Save-Data switches it off too.
  • Only the URL path is sent. Query strings and fragments are stripped on the client and re-stripped by the collector, because query strings can carry tokens.
  • The referrer is reduced to a host name. The endpoint sets no cookies and retains raw lines no longer than 24 hours, after which only daily aggregates remain.
  • While the endpoint is unset the client sends nothing at all: the site works exactly as it does today, minus measurement. No count is displayed anywhere, because there is no count.

How conversions actually join

Amazon's Associates report is aggregated by tag and date; it exposes no per-click identifier. The honest join is therefore tag × date × channel: this ledger's special_link_click counts on one side, the owner's authorised Associates report on the other, matched in the campaign ledger. This page never claims per-visitor attribution, and no conversion score or revenue forecast is derived here.

Turning it on

  1. Deploy tools/analytics_collector.py behind HTTPS on a host you control.
  2. Set window.ZONE3_ANALYTICS_ENDPOINT = "https://your-host/e"; on the page templates (one line; the shipped value is null).
  3. Load any page, open GET /stats, and confirm the test page_view arrived. Only then does measured data start choosing the next topic.

States above are also flagged for review: 0C4-F-05 (endpoint), 0C4-F-06 (Search Console), 0C4-F-07 (reader capture), 0C4-F-04 (Special Link validation).
