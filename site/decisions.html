Fix the front door: one clear home page with a single job

D-01 implemented

Implemented on /site/ in this session as a proposal preview so it can be judged by looking at it. Reversible: the page is new and nothing else was changed.

The problem
The repository root opens on a 19-item navigation bar whose first screen is an audit dashboard: six KPI tiles, then 17 navigation tiles, then a site map and a 12-row re-verification table. A reader who arrived to decide which air fryer to buy cannot find that decision anywhere on the first screen. That is the main reason the site reads as internal tooling rather than a marketing site.
What is proposed
Give the root a reader-first home page: a short promise, the three products as cards with what the listing actually states, one primary action, and a visible provenance line. Move the audit dashboard to its own page (it already exists at /dashboard/) and link it once as 'How this was verified'.
Evidence

  • OfficialI2-S01 A disclosure must be clearly and prominently stated on the site.
  • OfficialI2-S06 A disclosure is likely to be missed if it appears only in a footer or on an about page.
Effort
Low — one page template, no new data.
Expected effect
Editorial: converts first-time readers instead of losing them to an audit table. No traffic or conversion figure is claimed.
Risks
If the root is replaced, the audit pages must still be reachable in one click, or the verification record becomes hidden.
What it will not do
It does not add a price, a rating, a trend claim or a working buy link. It does not change any figure.

The problem

D-09 proposed

The problem
The brief asks for click and conversion tracking. Two constraints bite: per-visitor sub-tag attribution is prohibited, and artificial clicks are prohibited. What remains is Amazon's own reporting for orders, plus first-party page analytics on your own site.
What is proposed
Once the tag exists, read clicks and orders from Amazon's Associates reports. On your own site, use aggregate page analytics only. Add a privacy policy before adding any cookie-based analytics, and never assign a sub-tag to a visitor.
Evidence

  • OfficialI2-S02 Artificially generating clicks or creating Sessions is prohibited.
  • OfficialI2-S02 The site operator is responsible for disclosing cookie and pixel use.
  • OfficialI2-S03 The API returns a tagged detail page URL, which is the tracking surface Amazon itself provides.
Effort
Low to start, once Q1 and Q8 are answered.
Expected effect

Risks

Brand and tone prompt

P-01

Feed this into the design session so the output does not read as generated.

You are designing an editorial buying-guide site about kitchen air fryers. The reader is deciding between a 6-quart dual-basket basket fryer, a 26QT French-door air-fryer toaster oven, and an 8-quart single-basket fryer. Write and design for a sceptical reader who assumes affiliate sites are junk and will leave if they cannot see where a fact came from. Voice: plain, specific, confident where evidence exists and explicit where it does not. No exclamation marks. No 'in today's fast-paced world'. No sentence that praises a product without naming the listing fact that supports it. Never invent a number.

Page template prompt

P-02

The structure every reader-facing page should follow.

Build a page template with, in this order: a persistent disclosure banner above the navigation; a breadcrumb; an H1 that names the reader's question; two sentences of framing that contain no claim; the answer as a short table with a source link in every row; a 'what this page does not know' box; a single primary action that is either an active tagged link or a visibly disabled link labelled 'not active yet'; a provenance line naming the listing and the date it was read; and a footer repeating the exact sentence 'As an Amazon Associate I earn from qualifying purchases.' Never render an image loaded from an Amazon host. Never render a price or star rating.
Acceptance
  • Disclosure visible before any product content.
  • Every table row has a source link or an explicit blank-reason.
  • The primary action's state is unambiguous.
Guardrails
  • IP License 2(k) disclaimer present.
  • No iframe/embed of an Amazon page.
  • No price-tracking widget.

Article brief prompt

P-03

The format that keeps a guide from turning into filler.

Turn this reader question into a guide. Before writing, list every fact you intend to use and the listing or official page each came from. Drop any sentence whose fact is not on that list. Structure: the question, the short answer, a comparison table, three practical considerations drawn only from listed specifications, a 'what we cannot tell you' section naming the missing data and why it is missing, and a sources block. Do not use a superlative unless the source uses it. Do not describe using, testing or owning the product. Target 700–1,000 words with varied sentence length.
Acceptance
  • Fact list precedes draft.
  • Every retained sentence traces to the list.
  • The 'cannot tell you' section names a real gap.
Guardrails
  • No comparative performance claim absent from the listing.
  • No first-hand experience.

Anti-slop lint prompt

P-04

Run this over any draft before it is published.

Review the draft and flag, with the exact sentence: any paragraph longer than 90 words or more than two consecutive paragraphs of near-identical length; any three-item list that only restates the previous paragraph; any adjective doing the work of a fact ('incredible', 'game-changing', 'perfect for'); any hedge that hides a missing fact ('many users report', 'studies show', 'experts agree'); any sentence beginning with 'Whether you're'; any claim with no adjacent source; any repetition of the same section shape twice in a row. Return the list; do not rewrite.
Acceptance
  • Every flagged sentence is quoted.
  • Zero remaining unsourced evaluative sentences after the edit.
Guardrails
  • The lint list is a floor, not a definition of quality.

Compliance guardrail prompt

P-05

Hard constraints to paste into any content-generating session.

Hard constraints, no exceptions: never state a price, availability or star rating unless it came from Creators API or an Amazon-served link, and if it did, add the date/time stamp and the Amazon price disclaimer. Never show an Amazon-hosted image. Never use a URL shortener or an intermediate redirect. Never attach a sub-tag to a visitor. Never generate artificial clicks. Never bid on Amazon marks. Never frame an Amazon page. Never use Program Content to train a model. Never paraphrase a review you did not obtain through the API. If a rule conflicts with a design request, the rule wins and you say so.
Acceptance
  • Each constraint maps to a clause quoted in the source register.
Guardrails
  • These are legal constraints, not style preferences.

Data-safety prompt

P-06

Stops the build from filling blanks.

For every field in the product table, either cite the page it was read from in this session, or leave the cell empty and write one sentence saying why it is empty and what would fill it. Never estimate, average, interpolate, infer from a similar product, or carry a value forward from an older capture without a fresh read. If a value would make the page more persuasive but cannot be sourced, leave it out and say so on the page.
Acceptance
  • No filled cell without a source.
  • Every empty cell has a reason.
Guardrails
  • A blank with a reason is a feature; a guess is a defect.
