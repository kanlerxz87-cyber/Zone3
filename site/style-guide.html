House style, and the rules the build enforces

"Don't make it read like AI slop" is not a style. So this page turns it into something checkable: the sentences we are not allowed to write, the ones we are, and a script that fails the build when a page slips. The rules are not taste — most of them are Amazon's or the FTC's, with the link on the row.

Version 1 · in force on this site since 2026-11-16 · enforced by tools/cba81fa5_lint.py

Why a machine checks the prose

Amazon's own enrollment rule is that a site needs original content, and that content leaning on third-party material "must contain significant commentary, analysis, or transformation to any materials you include". A page that rephrases a listing title into three filler paragraphs fails that rule, a disclosure rule, and the reader — in that order. So the checks below are compliance as much as craft. CBA-S07

Required on every reader page

  1. One question per page, stated in the H1 as a question or a comparison, and answered in the first paragraph.
  2. Every factual sentence traceable to a listing, an Amazon programme page or an FTC page, with the link on the row it supports — not stacked in a footer.
  3. Arithmetic labelled as arithmetic. "8 ÷ 3 ≈ 2.7" is ours; the page says so rather than implying Amazon published it.
  4. A "what this page cannot tell you" block, naming the blanks and the reason for each.
  5. Disclosure in the top banner and in the footer, in the exact required wording.
  6. Provenance line: which pages were read, on what date, and that the review was done by the research desk (an agent session) with no human reviewer yet.
  7. No stored Amazon assets. Program Content images may not be hosted here, so pages carry text and links instead of product photography. gate V6

What a review pass means here, honestly

The proposals list asks for "a named human editor" (D-10) and for the guides to pass an editorial gate before publishing. Today four more guides went live. The pass they underwent is real and it is mechanical: the lint below runs against every page, and each factual row was re-read from the source that day. What it is not is human — so the byline says "Air Fryer Field Notes desk (an agent-run research session, no human reviewer yet)" rather than inventing a person with a first name and a taste for air fryers. A fake reviewer is worse than a fake review.

The lint

tools/cba81fa5_lint.py walks every page under site/ and fails the build on: a price or rating pattern; an experience claim; a hype word from the list above; a missing disclosure banner or footer; more or fewer than one <h1>; a table row without an official source link; a stored Amazon asset; a non-HTTPS or shortener outbound link; a broken internal link; a page not listed in site/site-index.json. It is deliberately boring and deliberately mechanical — that is what makes it fair to a page nobody human has read yet. Run it with python3 tools/cba81fa5_lint.py; it prints one line per finding and exits non-zero.

How a page gets made here, start to finish

  1. Pick the question a shopper actually has, from the listing text — not from a keyword tool.
  2. Quote the sentences that answer it, with the page each came from and the date read.
  3. Write the analysis the quote cannot give: what the spec means when you are holding a shopping list.
  4. Write the blanks before the body text, so the shape of the page admits them.
  5. Run the lint, re-read every source link, and only then add the page to the site index and the sitemap.
